The brief

A storefront that respects how hardware is actually bought.

Hardware purchasing is rarely a single click. It involves quantities, alternatives, project timing and a conversation. This concept keeps that reality visible instead of forcing it into a generic checkout flow.

  • Search by product, SKU, brand or department.
  • Build a multi-product request with quantities and per-line notes.
  • Manage catalogue, stock signals and request follow-up in one demo admin.
  • Designed from 360px phones upward, with keyboard-visible focus states.

What this concept demonstrates

Three workflows, fully clickable.

Catalogue operations

Create, edit, unpublish and delete listings. SKU uniqueness, required fields and image fallbacks are enforced in the demo layer.

Inventory signals

Quantities and low-stock thresholds are tracked separately from “unknown” stock, so a missing count is never shown as zero.

Request handling

Move requests through five statuses, add internal notes and print a demonstration document stamped clearly as unofficial.

An honest demonstration

No backend. No invented approvals.

This project is an independent proposal by Thomas Hondo Chacha. It is not commissioned, endorsed or operated by Marowa Store. Product entries, prices, stock levels and request records are sample data. The admin access code is public by design and must never be treated as production security.
